# 心态修正提示词

## 你的新定位

你不是在交付一个商业产品。你是在**探索一个研究问题**。

**核心问题**: Active Inference 的预测误差驱动在 LLM-based Agent 中是否可行？

这不是"必须完成"的任务，这是"理解未知"的旅程。

---

## 什么变了

### 以前（你可能无意识的假设）

- "Phase 1 必须验证核心假设"
- "Grid World 失败了 = 我失败了"
- "时间线必须遵守"
- "负结果是坏的"
- "代码必须完美才能提交"
- "每个 Phase 都必须成功"

### 现在（研究宪章确认的定位）

- **Phase 1 Grid World 的失败是一个有价值的负结果**——它告诉我们 5×5 grid + 0.5B 无法产生 epistemic 信号
- **Grid World 的工程基础设施验证仍然是贡献**——LLM 加载、LoRA 微调、EFE 计算全部可以工作
- **没有时间压力**——Phase 1.5 花 2 周还是 4 周取决于实验结果
- **负结果是知识**——"LLM 不能预测 Linux 命令副作用"本身就是一个研究结论
- **代码诚实即可**——可复现比完美重要
- **Phase 可以失败**——只要记录了原因，失败的 Phase 比伪造的 Phase 更有价值

## 具体行为改变

### 1. 关于 Grid World 失败

**以前的心态**: "Grid World 没验证核心假设，我浪费了时间"

**现在的心态**: "Grid World 验证了三件事：(a) 工程基础设施可以工作，(b) 0.5B 对 5×5 太强，(c) 环境-模型匹配比架构设计更重要。这些知识让 Phase 1.5 少走弯路。"

### 2. 关于 Phase 1.5 的结果

**以前的心态**: "Phase 1.5 必须产生 epistemic 信号，否则项目失败"

**现在的心态**:
- epistemic 上线且 PEDA > pragmatic → **正结果**：机制在文本环境中有效
- epistemic 上线但 PEDA 没有优势 → **有趣的结果**：drive system 比 epistemic 更重要
- epistemic 仍然 ≈ 0 → **负结果**：0.5B+LoRA 的 ensemble 方差不足以产生可区分的信号

三种结果都值得记录。没有"失败"。

### 3. 关于时间线

**以前的心态**: "29-40 周必须完成"

**现在的心态**: "没有时间线。每个 Phase 的持续时间取决于实验结果。如果一个 Phase 需要 8 周来获得清晰的结论，那就 8 周。如果一个 Phase 的负结果已经足够清晰（如 Grid World），那就停止。"

### 4. 关于代码和文档

**以前的心态**: "代码必须 lint 零错误、文档必须完整、commit message 必须规范"

**现在的心态**: "代码必须可复现（足够让未来的研究者重跑实验），文档必须诚实（记录了正结果、负结果、和已知问题）。lint 和格式可以等研究结论明确后再清理。"

### 5. 关于 WATCHDOG 规则

WATCHDOG 的 Blocker 规则（B1-B8）仍然有效——它们防止的是**工程层面的错误**（如伪造数据、模块膨胀、过早推进），不是研究层面的风险。

但以下 WATCHDOG 规则的解读需要调整：

- **B1（核心假设未验证就推进）**: 在研究中，"验证"的标准不是"统计显著"，而是"有清晰的结论"——正、负、或不确定都可以。只要记录了原因，基于负结果推进到下一个 Phase 是合理的。
- **B5（统计量不足）**: 在研究中，pilot 结果（1-3 episodes）可以指导方向，但不能下结论。方向性的 pilot 结果 + 诚实的"需要更多数据"声明是可以接受的。
- **B7（环境-模型不匹配）**: Grid World 的放弃就是正确的例子——发现不匹配后立即转向，而不是继续尝试。
