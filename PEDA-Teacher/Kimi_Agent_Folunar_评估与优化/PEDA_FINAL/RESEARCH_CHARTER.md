# PEDA 研究宪章

**项目定位**: 研究探索  
**核心问题**: Active Inference 的预测误差驱动在 LLM-based Agent 中是否可行？  
**非目标**: 商业产品交付、时间表约束、性能指标达标

---

## 研究问题

PEDA 试图回答一个具体问题：

> **当 Agent 的 World Model 不完美时，预测误差（prediction error）是否能作为一种内在驱动信号，引导 Agent 主动探索不确定性区域，从而比纯目标导向的行为更有效？**

这个问题分解为三个子问题：

1. **信号问题**: LLM-based World Model 能否产生可测量的、与预测质量相关的预测误差信号？（epistemic error > 0）
2. **驱动问题**: 这个预测误差信号能否驱动 Action Generator 选择探索性行为？（EFE 有效）
3. **效果问题**: 由预测误差驱动的探索是否比基线（纯 pragmatic、纯随机）更有效？（PEDA > baseline）

三个子问题层层递进。如果任何一个子问题的答案是"否"，整个假设在此条件下不成立——**但这本身就是一个有价值的研究结论**。

---

## 负结果标准

PEDA 明确接受以下负结果，并会将它们记录为有效结论：

| 负结果 | 含义 | 价值 |
|--------|------|------|
| LLM 无法产生可区分的 epistemic 信号 | 0.5B+LoRA 的 ensemble 方差太小 | 说明当前模型规模/微调方法不足以支持 FEP 框架 |
| EFE 在 horizon=2-3 时退化为贪心 | 推理速度限制使多步规划不可行 | 说明 Active Inference 需要特定硬件条件才能展现优势 |
| 预测误差驱动不如纯 pragmatic | 信息增益在真实环境中不如距离最小化有效 | 说明 FEP 的 epistemic value 在某些环境中不如 pragmatic value |
| 冷启动无法解决 | 初始数据质量太低导致学习循环断裂 | 说明 bootstrap 策略或模型先验知识不足 |
| 任何 Phase 失败 | 该环境下的条件不满足假设验证要求 | 说明 PEDA 假设的适用范围比预期更窄 |

**关键原则**: 负结果不是项目失败，而是知识。一个诚实记录的负结果比一个人为制造的"成功"更有科学价值。

## 产出形式

PEDA 的产出是开源的研究资产，不是商业产品：

1. **代码**: GitHub 仓库（MIT 许可证），包含完整的实验可复现流程
2. **文档**: 实验报告（Markdown），包含正结果、负结果、和未解决问题
3. **数据**: 实验日志、训练数据、评估结果（开放下载）
4. **分析**: 对 Active Inference + LLM 结合的可行性评估

**不产出**: 商业产品、API 服务、用户文档、性能基准排名

---

## 时间线原则

- **没有硬性截止日期**
- 每个 Phase 的持续时间取决于实验结果，不是预先设定的时间
- 如果一个 Phase 需要比预期更长的时间来获得清晰的结论，那就花更长的时间
- 如果一个 Phase 的负结果已经足够清晰（如 Grid World 连续三次无法产生 epistemic 信号），那就停止，不要继续投入

## 风险接受度

| 风险 | 产品心态 | 研究心态（PEDA） |
|------|---------|-----------------|
| Phase 失败 | 不可接受 | **可接受，只要记录了原因** |
| 时间超支 | 不可接受 | **可接受，只要在学习** |
| 代码不完美 | 不可接受 | **可接受，只要可复现** |
| 负结果 | 不可接受 | **可接受，只要诚实报告** |
| 理论假设不成立 | 项目失败 | **有价值的知识** |

---

## 最终判断标准

PEDA 项目成功的标准不是"交付了一个自主 Agent"，而是：

> **我们是否对"Active Inference 在 LLM-based Agent 中的可行性"有了比项目开始前更深的理解？**

如果这个问题的答案是"是"——无论最终 Agent 是否自主、无论是否按期完成——PEDA 就是成功的。
